# Plan — Listnr V1 (2026-08-22)

Successor of `docs/plans/2026-08-22-listnr-v0.md`. V0 (four tabs, player, notes, sample
library) stands; V1 makes the app real: iOS 26 shell, locked mockup UI 1:1, folder import of
the user's own M4B files, real chapters, a sleep timer that survives the lock screen.

Binding decisions (owner, 2026-08-22): scheme **Purple only** · min iOS **26**, native Liquid
Glass `TabView` · import = user picks a **folder** (security-scoped bookmark), app indexes all
**M4B** inside and rescans on launch/foreground · **real chapters** from `AVAsset` metadata,
synthetic splits dropped · sleep timer fully built (15/30/60/Off, stops playback) · notes stay
(pencil bottom-right) · direct device install from Xcode with the paid team · `project.yml` is
the project source of truth (`xcodegen generate` after every file add) · `scripts/verify.sh`
and `scripts/test.sh` green at every step.

Design source of truth, in this order: `docs/mockups/audiobook.html` + `docs/mockups/library.html` +
`docs/mockups/app.js` + `docs/mockups/kit.css` → `docs/DESIGN.md` → this plan. Serve the mockups with
`cd mockups && python3 -m http.server 8123` and compare screen by screen before each UI step.
One exception: the **mini-player (step 3b) is not in the mockups yet** — Library, Reader and Scan
there end at the tab bar. Build it from this plan's tokens and rails; the mockups get the
accessory in a separate pass, and until then a missing accessory in `library.html` is not a diff.

Preflight, once: `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`
(verified on this machine: Xcode 26.6, SDK iphoneos26.5, iPhone 17 Pro simulator present).

Global stop rule for every step: if the step's validation command fails twice in a row on the
same cause, revert that step's diff (`git checkout -- <paths>`), write the reason into
`docs/IDEAS.md`, and continue with the next step. Never leave the tree with a red `scripts/verify.sh`.

3. `LibraryIndexer` (actor, off the main actor):
   - enumerate the folder recursively, `skipsHiddenFiles`, keep `pathExtension.lowercased() == "m4b"`;
   - per file build an `AVURLAsset` and read with async loaders only:
     `load(.duration)`, `load(.commonMetadata)` for `.commonKeyTitle`, `.commonKeyArtist`,
     `.commonKeyArtwork`, `loadChapterMetadataGroups(withTitleLocale:containingItemsWithCommonKeys:[.commonKeyTitle])`
     (verified in this SDK) for `[Chapter]` — each group's `timeRange` gives start + duration and

   computed `chapters` property go away. `BookRecord` gains the matching columns plus
   `chaptersData: Data` (JSON of `[Chapter]`); bump the schema by adding fields with defaults so
   an existing store migrates lightly.
6. Rescan: `AppModel.rescanSources()` runs on launch after the store loads, and on

   - API: `CoverView(book:)` stays the entry point; the drawing lives in

   - **Lock screen**: `AppModel.updateNowPlaying` renders the fallback through `ImageRenderer`

     always populated — a book with no embedded art must not show a blank lock screen.
   - Test `Tests/Unit/CoverFallbackTests.swift`: the tone is stable for a given title across
     runs, different titles spread across the five tones, and an `ImageRenderer` snapshot of a

## Step 7 · Sleep timer end to end

Files: `App/Sources/Kit/AudioPlayerEngine.swift`, `App/Sources/Kit/PlayerEngine.swift`,
`App/Sources/AppModel.swift`, `App/Sources/Player/PlayerView.swift`,
`Tests/Unit/SleepTimerTests.swift` (new).

Changes:
1. Deadline instead of decrementing: the engine stores `sleepDeadline: Date?`, and
   `sleepRemaining` is computed as `deadline.timeIntervalSinceNow`. Decrementing by tick drifts
   and stops making sense while the app is suspended; a deadline does not.
2. Firing: on every tick (and on `applicationDidBecomeActive`), if `sleepRemaining <= 0` →
   `pause()`, clear the deadline, persist the position, update now-playing so the lock screen
   shows a paused book. Playing must **stop**, not duck.
3. Arming while paused is allowed and does not start playback. `Off` clears the deadline.
4. Pausing manually leaves the timer running (matches the mockup); re-arming resets it.
5. UI: minutes left beside the moon in the top row (12pt `ink3`, "28m", `<1m` under a minute),
   updated from the engine's `onChange` tick.
6. Tests: arm 15 → advance 14:59 → still playing; advance past → paused, `sleepRemaining == nil`;
   `Off` clears; arming twice resets the deadline. `MockEngine` gets the same deadline semantics
   with an injectable clock so the tests stay wall-clock free.

Validation:
```bash
scripts/test.sh dev
scripts/verify.sh
```
Device check (step 8 covers it): arm 15 min, lock the phone, confirm the lock-screen controls
still show the book and that playback stops at the deadline.

Stop rule: if the timer misses while the app is suspended, do not add a background task — the
audio background mode keeps the process alive while playing, and the deadline catch-up on the
next tick is the fallback.

## Risks with the iOS 26 / AVFoundation APIs — check these first in the SDK

1. **Liquid Glass is opt-out, not opt-in.** Building against the iOS 26 SDK gives the glass tab
   bar automatically; `UIDesignRequiresCompatibility` in `App/Info.plist` would switch it off.
   Check first: that key is absent (it is, today).
2. **`Tab` / `tabBarMinimizeBehavior` / `tabViewBottomAccessory` / `TabViewBottomAccessoryPlacement`**
   are all present in the 26.5 SwiftUI interface (verified by grep against the SDK's
   `.swiftinterface`). V1 uses all four: `Tab` in step 0, the other three in step 3b.
   `glassEffect` lives in **SwiftUICore**, not SwiftUI — V1 needs no custom glass surface, since
   the tab bar and the accessory get theirs from the system.
3. **Deployment target 26.0 vs SDK 26.5**: fine, but the phone must run iOS 26 — check the
   device's version before step 8, since a lower phone cannot install the build at all.
4. **`AVAudioPlayer` with security-scoped iCloud files.** `AVAudioPlayer(contentsOf:)` wants the
   whole file locally: an iCloud-Drive M4B that is not downloaded will fail. Check for
   `URLResourceValues.ubiquitousItemDownloadingStatus` and call
   `startDownloadingUbiquitousItem(at:)` before loading; if that turns out to be flaky for the
   20-hour files this app is for, switch the engine to `AVPlayer` (streams, no full read) —
   the `PlayerEngine` protocol exists exactly for that swap.
5. **Security-scoped access must wrap playback too**, not only indexing: the engine loads a file
   inside the picked folder, so `startAccessingSecurityScopedResource()` has to be held for the
   life of the loaded book, not just for the scan.
6. **Chapter metadata is per-language.** `loadChapterMetadataGroups(withTitleLocale:)` returns
   nothing when the locale does not match; use
   `loadChapterMetadataGroups(bestMatchingPreferredLanguages:Locale.preferredLanguages)` as the
   fallback before concluding a file has no chapters — German audiobooks are the common case here.
   **Both of those still miss the common case (found 2026-08-22 while building step 5).** Real m4b
   files routinely tag the chapter text track `und`, which matches neither the current locale nor
   any preferred language, so both calls return zero groups on a file that plainly has chapters.
   A third pass is required and is the one that actually fires: iterate
   `asset.load(.availableChapterLocales)` and retry per declared locale. Order:
   current locale, then preferred languages, then declared locales.
7. **SwiftData migration.** Adding columns to `BookRecord` and a new `FolderRecord` is a
   lightweight migration only if every new property has a default. Check that before shipping to
   the device, otherwise the app comes up with an empty library after an update.
8. **`Timer` under the glass tab bar** — none of the UI changes touch timing, but the player's
   0.25 s ticker must stay on `RunLoop.main` in `.common` mode so scrubbing does not freeze the
   clock.

## Amendments — YAGNI pass (2026-08-22, implementation)

Applied while executing. Each one removes work the plan asked for that nothing needs yet.

1. **Step 5.4 dedupe drops `duration` from the identity key.** Duration needs a full `AVAsset`
   load, so keying on it forces a re-read of every file on every rescan. Identity is
   `relativePath` first; a row that is no longer at its path is matched to a new path by
   `fileSize` before it is marked missing. Same behaviour for the move case, no extra I/O.
2. **Step 5.8 lock-screen artwork is not cached to disk.** `ImageRenderer` runs once per loaded
   book and the `UIImage` is held in memory by `AppModel`. A book is loaded once per session;
   a PNG file cache buys nothing and adds an eviction problem.
3. **Step 5.2 import sheet drops the "hairline that fills once".** Scanning shows the file name
   being read as plain text, then the result lines. There is no progress fraction to be honest
   about until the enumeration finishes, so an animated bar would be decoration.
4. **`NotesListView` (App/Sources/Player/NoteSheet.swift) is deleted.** It is dead code — nothing
   has ever presented it. The note sheet's own previous-notes list (step 4.5) is the only list.
5. **`ProgressLine` (App/Sources/Theme.swift) is deleted** with step 2, as step 2.5 allows: the
   band lives inside the cover now and no other screen draws a progress line.
6. **`ChapterMath.timeLeftInChapter` is deleted** with step 3.5, together with `Fmt.chapterLeft` —
   the middle scrubber time is the only caller.
7. **A missing book is shown, not hidden.** Step 5.4 marks rows missing but the plan never says
   what the UI does. The library row reads `Audiobook · missing` and drops to opacity .5; tapping
   it does not open the player. Anything else is a dead control.
