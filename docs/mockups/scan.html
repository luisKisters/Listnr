Scan a page, land on the second

You read the paper copy on the train and want the audiobook to carry on from there. Point the camera at the page: the text is read on the device, matched against a transcript of the audio, and one second comes back. You confirm it, then the player seeks there. Nothing jumps on its own — a wrong guess that moves the book is worse than a guess you can refuse.

One skeleton, in every state. The close slot, the frame and one button stand in exactly the same place and at exactly the same size from the first tap to the last; only what is inside them changes. The frame keeps its four brackets and takes every pixel left over between the head and the button, so it is the one box that flexes and the button's place in the gap follows from it. The button is the state machine — and it is a filled accent button in every state, shutter to "Prepare this book". While it works, the fill stays and the loader turns inside it.

The loop is now four steps, not three: the page is read, then what was read is searched for in the transcript, and only then does a match or a miss come back. They can fail apart, so they say different things.

Everything below is live. The first phone starts at the shutter and walks the whole loop — its shots alternate between a hit and a miss, so both endings are reachable — and the others open straight into the state they are named for. Tap the book title on any of them and the frame becomes the drum. Turn the guides on in the bar: everything lands on the same two rails as every other screen.

The one screen, in every state

Idle

The viewfinder is a dark box with a bracket frame, not a photograph: a rendered page would promise a fidelity nothing here has. The hint stands in the middle of the frame, where everything the frame says stands, and leaves for good once a scan has been taken — it has said everything it can say. The book being matched is named on the line, because a scan that silently searched the wrong book would explain none of its failures.

Reading

The frame freezes and dims, and the button keeps its fill with the loader turning inside it — same size, same place, so nothing on the screen moves and nothing about the button suggests it went away. There is no arc claiming a number: OCR has no honest fraction.

Searching

The words are in hand; this is the transcript being searched. Same button, same loader — only the frame changes its line, because the two steps fail for different reasons: a page too dark to read is not a page whose words are nowhere in the book, and the failure that follows has to be able to say which one happened.

Match

The result lands where the page was, centred in the frame's own box: the snippet quoted back first, then the second and the chapter. Three lines of the book's own words say more about whether the match is right than any confidence score would. Refusing is the close at the top right — it goes back to the viewfinder, not to an apology, and it is far away from the thing that moves the book.

Choosing the book

The frame's box becomes the same drum the chapters use — the iOS wheel, settling on a row to choose it, no second component invented for the same act. Each row says on its right end whether that book is transcribed, as quiet plain text, because picking a book that cannot be scanned is the one mistake this list exists to prevent.

No match

A plain sentence, then what to do about it. The failure is named inside this book, because that is what actually happened: the text was read fine and found nowhere. A page of dialogue or a chapter heading gives the matcher almost nothing to work with, so the second line asks for more words rather than blaming the camera.

Not prepared

Scanning is worthless without a transcript, so the book that has none says so before the shutter, not after it: the frame carries the reason and the button carries the one thing to do about it. This is the state the disc cannot hold — four words do not fit in a 64px circle, which is what the shape axis is for.

The model is missing

Preparing a book needs a 460 MB speech model that arrives once per install, so on a fresh phone that is the real first step and the button says so instead of promising a preparation it cannot start. The sheet asks once, and it is honest about the two things that hurt: it downloads only while the app is open, and there is no pause — the download cannot resume, so the second control is a stop that admits the next one starts at zero. When it lands the sheet closes itself and the book the tap was about starts preparing: the user already asked.

Preparing

This is the one state that earns a number. Transcription walks the audio start to end and genuinely knows how far it got, so the loader inside the fill is the fraction rather than a turning arc. Same footprint, same fill, doing the honest version of the same job. It runs behind playback, which the frame says out loud so nobody sits and watches it.
